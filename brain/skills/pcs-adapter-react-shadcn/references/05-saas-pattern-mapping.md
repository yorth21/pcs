# 05 — SaaS Pattern Mapping (`tpl-*`, `org-*`, `mol-*` → `shadcn/ui`)

This reference maps every page template (`tpl-*`), organism (`org-*`), and molecule (`mol-*`) of the stack-agnostic `pcs-saas` catalog to concrete React 19 + TypeScript + Tailwind CSS v4 + vanilla `shadcn/ui` composition. The `pcs-saas` catalog stays the source of truth for anatomy, behaviour, states, and acceptance checks (`AC-*`); this file only answers **which primitive, which variant, which classes, which ARIA wiring, and where the code lives**.

Use it node by node: for every node of a Page Composition Spec (`pcs-saas` `references/04-template-decision-tree.md` §4), find the row here, then start from the matching blueprint in `assets/templates/`.

---

## 1. Build Procedure per Page Composition Spec

1. Read `pcs/design/inventory.md`. For every `org-*` / `mol-*` node, apply the `pcs-saas` `references/06-ui-inventory.md` §4 Reuse Rule **before** reading the mapping rows below: `reuse` → import the inventory component unchanged; `extend` → add the missing capability in place; `new` → compose from the row below; `deviate` → only with the spec's justification.
2. Copy the blueprint named in §5 for the spec's `tpl-*` ID into `src/features/[feature]/[subfeature]/`, split it into the files listed in its header comment, and rename the generic domain to the spec's object.
3. Replace each region with the spec's region tree, keeping the blueprint's state branches; every `S1`–`S7` cell of the spec's state matrix maps to one branch named in §3.
4. Wire URL search params exactly as the spec's data contract lists them, using the router rules of `03-tanstack-rhf-zod-patterns.md` §1.
5. Keep the blueprint's `AC-*` comments next to the code that satisfies them so the verifier can trace each check.

Templates without a blueprint file (`tpl-index-cards`, `tpl-onboarding`, `tpl-auth`, `tpl-billing`, `tpl-activity-log`, `tpl-search-results`, `tpl-import-export`, `tpl-system-page`, `tpl-app-shell`) are composed from the closest blueprint named in §5 plus the organism rows in §6.

## 2. Assumed Project Infrastructure

Blueprints import only these project modules besides `@/components/ui/*`. If the project lacks one, create it with this contract (it is shared infrastructure, so it lives in `src/lib/` or `src/hooks/`).

| Module | Exports used by blueprints | Contract |
|--------|----------------------------|----------|
| `@/lib/utils` | `cn` | Standard `shadcn/ui` class merger. |
| `@/lib/api-client` | `apiClient`, `ApiError` | `apiClient.get<T>(path, { params? })`, `.post<T>(path, body)`, `.patch<T>(path, body)`, `.delete<T>(path)`; throws `ApiError` with `status: number`, `message: string`, `referenceCode?: string`, `fieldErrors?: Record<string, string>`. |
| `@/lib/format` | `formatCurrency`, `formatNumber`, `formatCompactNumber`, `formatPercent`, `formatDate`, `formatDateTime`, `formatRelativeTime` | Locale- and timezone-aware wrappers over `Intl.*` per `pcs-saas` `03-molecules-and-patterns.md` §6; each accepts an optional trailing `Intl` options object (`formatCurrency(value, currency, { compact })`). Never format inline with `toFixed`. |
| `@/hooks/use-mobile` | `useIsMobile` | `true` below `640px` (catalog `mobile`). |

Install these `shadcn/ui` primitives before building: `alert`, `alert-dialog`, `avatar`, `badge`, `breadcrumb`, `button`, `calendar`, `card`, `chart`, `checkbox`, `command`, `dialog`, `drawer`, `dropdown-menu`, `empty`, `field`, `input`, `input-group`, `kbd`, `pagination`, `popover`, `progress`, `resizable`, `scroll-area`, `select`, `separator`, `sheet`, `sidebar`, `skeleton`, `sonner`, `spinner`, `switch`, `table`, `tabs`, `textarea`, `toggle-group`, `tooltip`.

### 2.1 Breakpoints and Density Tokens

| Catalog term | Tailwind v4 |
|--------------|-------------|
| `mobile < 640px` | unprefixed utilities (mobile-first) |
| `tablet 640–1023px` | `sm:` |
| `desktop >= 1024px` | `lg:` |
| `wide >= 1440px` | `wide:` after adding `@theme { --breakpoint-wide: 90rem; }` to `src/index.css` |
| `compact` density | table rows `h-10` (`40px`), controls `h-8`/`h-9` (`size="sm"` on `Button`, `h-8` on `Input`), card padding `p-4` |
| `comfortable` density | table rows `h-12`–`h-14`, controls `h-10` (`Input` default `h-9` is acceptable only when the inventory says so), card padding `p-6` |
| Page gutter | `px-4 lg:px-8`; header → content gap `gap-6 lg:gap-8` |
| Content widths (`pcs-saas` `05` §4) | fluid `max-w-[1600px]`; cards/dashboard `max-w-screen-xl` (`1280px`) to `max-w-[1440px]`; record `max-w-screen-xl` with main `max-w-[840px]`; forms/settings/wizard `max-w-[720px]`; auth/onboarding/system `max-w-[440px]`–`max-w-[560px]` |

Density is applied with a `data-density="compact|comfortable"` attribute on the region root plus conditional classes; never mix densities inside one `Table`.

## 3. State Codes → Rendering

| Code | Primary composition | Required wiring |
|------|---------------------|-----------------|
| `S1` Loading | `Skeleton` blocks with final geometry inside the real layout; header and filter bar render immediately. Refetch: keep data via `placeholderData: keepPreviousData`, show `Spinner` (size `size-4`) in the toolbar or a `h-0.5` `Progress`-style bar at the region top. | Region root `aria-busy="true"`; skeleton container `aria-hidden="true"`; one `<span className="sr-only" role="status">Loading {region}</span>`. Delay skeletons by `200ms` for fast loads. Never a full-page spinner after the shell renders. |
| `S2` Empty first-use | `Empty` + `EmptyHeader` + `EmptyMedia variant="icon"` + `EmptyTitle` + `EmptyDescription` + `EmptyContent` with one `Button` (primary) and optional `Button variant="outline"`. | Shown when unfiltered total is `0`; filter bar not rendered. `EmptyTitle` renders the region heading level. |
| `S3` Empty no-results | Same `Empty` with title naming the query/filters and `Button variant="outline"` "Clear filters". In tables: inside `TableBody` as one `TableRow` with `TableCell colSpan={columns}`. | Toolbar and chips stay visible; never a create action. Live region announces "0 results". |
| `S4` Error | `Alert variant="destructive"` + `AlertTitle` "Couldn't load {region}" + `AlertDescription` + `Button variant="outline" size="sm"` "Retry" (calls only that query's `refetch`). Inside the failing region, `min-h` equal to the region's normal height. | `role="status"` on first render, switch to `role="alert"` only after a user-triggered retry fails. Reference code via `ApiError.referenceCode` rendered `font-mono tabular-nums`. |
| `S5` No permission | Page: `Empty` system-page variant `no-access` inside the shell (see `tpl-system-page`). Region: `Alert` (default variant) with `LockKeyhole` icon "You don't have access to {region}". Action: omit the element when never grantable; `Button disabled` wrapped in `Tooltip` naming the required role when requestable (wrap in `<span tabIndex={0}>` so the tooltip is reachable). | Route a `403` `ApiError` to the no-access branch, never to `S4`. |
| `S6` Partial / degraded | `Alert` (default variant) styled with warning tokens (`border-warning/50 bg-warning/10 text-foreground`, icon `text-warning`) at page top, below the header; never dismissible while the condition holds. Per-widget staleness: `text-xs text-muted-foreground` "Updated {relative}". | `role="status"`. Add `--warning`, `--success`, `--info` tokens to `@theme inline` (`04-tailwind-v4-tokens-and-motion.md` §1) when missing. |
| `S7` Success feedback | In-place edit: the changed value plus `text-xs text-muted-foreground` "Saved" for `2s`. Out-of-view effect: `toast.success("{Object} created", { action: { label: "View", onClick } })`. Reversible destructive: `toast("{Object} archived", { action: { label: "Undo", onClick }, duration: 6000 })`. Page create: `navigate({ to: record })` then toast. Highlight: `data-highlight` row class `bg-accent/40 transition-colors duration-2000`. | `Toaster` mounted once in the shell with `position="bottom-right"` and `visibleToasts={3}`. |

## 4. Feature-Folder Placement

Catalog organisms are cross-cutting by nature, but the Promotion Rule of `01-folder-and-component-architecture.md` §2 still decides location: compose inline in the feature first; promote to `src/components/` the moment a second feature needs the same organism. A promoted organism MUST own behaviour (state branches, ARIA, URL wiring); a component that only forwards props to one primitive is a forbidden wrapper.

| Catalog unit | Single-feature location | Promoted location (`>= 2` features) | File name pattern |
|--------------|-------------------------|-------------------------------------|-------------------|
| `tpl-*` page composition | `src/features/[feature]/[subfeature]/index.tsx` | never promoted | `index.tsx` (screen entry) |
| Route + search schema | `src/routes/_app/[feature]/...` (thin) + `schemas/[feature]-search.schema.ts` | — | `[feature]-search.schema.ts` |
| Query keys + hooks | `hooks/use-[feature].ts` | — | `use-[object]s.ts`, `use-[object].ts` |
| `org-app-sidebar`, `org-top-bar`, `org-page-header`, `org-banner`, `org-section-error`, `org-empty-state` (behavioural parts) | — (always shell or shared) | `src/components/layout/` | `app-sidebar.tsx`, `top-bar.tsx`, `page-header.tsx`, `page-banner.tsx`, `section-error.tsx` |
| `org-data-table`, `org-filter-bar`, `org-bulk-action-bar`, `mol-pagination`, `mol-facet-filter`, `mol-filter-chip` | `components/[object]-table.tsx`, `[object]-columns.tsx`, `[object]-toolbar.tsx` | `src/components/data-table/` | `data-table.tsx`, `data-table-toolbar.tsx`, `data-table-pagination.tsx`, `data-table-faceted-filter.tsx`, `data-table-bulk-bar.tsx` |
| `org-sectioned-form`, `mol-form-field`, `org-auth-form`, `org-file-dropzone` | `components/[object]-form.tsx` | `src/components/form/` | `form-input.tsx`, `form-select.tsx`, `file-dropzone.tsx` |
| `org-detail-panel`, `org-destructive-confirm`, `org-kpi-row`, `org-chart-panel`, `org-activity-feed`, `org-comment-thread`, `org-usage-meter`, `org-plan-comparison`, `org-card-grid`, `org-wizard-stepper` | `components/[object]-{sheet,delete-dialog,kpis,chart,activity,comments,usage,plans,grid,stepper}.tsx` | `src/components/layout/` (frames) or `src/components/data-table/` (collections) | `detail-sheet.tsx`, `destructive-confirm-dialog.tsx`, `kpi-row.tsx`, `activity-feed.tsx` |
| `org-command-palette`, `org-notification-center`, `org-feedback` (`Toaster`) | — | `src/components/layout/` | `command-palette.tsx`, `notification-center.tsx` |
| `mol-status-badge` vocabulary | `components/[object]-status-badge.tsx` (status → role map) | `src/components/ui/status-badge.tsx` only when `>= 2` objects share the role styling | — |

Never put `Organism`, `Molecule`, or `Template` in a path or identifier; name by object and role (`InvoiceTable`, `InvoiceStatusBadge`).

## 8. Verification Hooks

- Every blueprint comment `// AC-*` marks the element a Playwright test should target; prefer `getByRole` with the accessible names listed in §6–§7.
- A page passes adapter verification only when every `S1`–`S7` cell of its spec maps to one of the branches in §3 and the rendered DOM contains the ARIA wiring listed in the organism row.
- Two project components implementing the same `org-*` ID is a deviation (`pcs-saas` `06` §4); report it, never pick one silently.
